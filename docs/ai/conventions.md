# Project Conventions

_Updated: 2026-09-11_

- Date verified facts and attach commands, commits, or file paths as evidence.
- Label future work as intent; never describe unverified work as complete.
- Keep one active task file per unit of work and keep `tasks/ACTIVE.md` synchronized.
- Task checkpoints include objective, scope, acceptance criteria, context, changed files, evidence, risks, external state, worktree/base commit, and exact next action.
- Decision records explain context, options, choice, and consequences without duplicating live state.
- Use strict TypeScript, small components, semantic HTML, accessible names, and visible focus states.
- Keep secrets and chat-only knowledge out of project memory. The required task field is `Information only in chat: none`.
